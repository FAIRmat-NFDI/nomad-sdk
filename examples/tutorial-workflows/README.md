# Recreating the NOMAD workflow tutorial

How to rebuild the workflows from the
[NOMAD workflow tutorial](https://fairmat-nfdi.github.io/nomad-tutorial-workflows/latest/)
with `nomad-sdk`: in the **playground** (no code, no login) or in **Python**.

| Tutorial part | Workflow | Files | Playground | Python |
| --- | --- | --- | --- | --- |
| [Part 1 – Core](https://fairmat-nfdi.github.io/nomad-tutorial-workflows/latest/core/) | MD equilibration: Emin → Equil-NPT → Prod-NVT | one upload | **yes** ([A](#a-md-equilibration-in-the-playground)) | yes |
| [Part 4 – Custom workflows](https://fairmat-nfdi.github.io/nomad-tutorial-workflows/latest/workflows/) | Project workflow linking 4 uploads | several uploads | not yet (needs upload / entry IDs) | **yes** ([B](#b-project-workflow-across-uploads-python)) |

The difference is the kind of reference the workflow file contains:

* **Same upload**: `../upload/archive/mainfile/<path>#/...`. You only need the files, so this
  works offline in the playground.
* **Across uploads**: `../uploads/<upload_id>/archive/<entry_id>#/...`. You need the IDs of
  uploads that are already processed. The playground will get these through
  *Login and select* (greyed out for now); until then, use Python.

## A. MD equilibration in the playground

**1. Get the files.** Download `workflow-example-water-atomistic.zip` from the tutorial's
[example upload](https://nomad-lab.eu/prod/v1/gui/user/uploads/upload/id/WWGPCK-URqGmJWkh_9tElQ)
and unpack it.

```text
workflow-example-water-atomistic/
├── workflow.archive.yaml   ← the tutorial's result; delete or rename it, you will generate it
├── Emin/mdrun_Emin.log     (GROMACS mainfile)
├── Equil-NPT/mdrun_Equil-NPT.log
└── Prod-NVT/mdrun_Prod-NVT.log
```

Folder names can differ slightly between versions of the download (`Equil-NPT` or `Equil_NPT`).
The playground uses whatever is on disk.

**2. Open the folder.** Open the playground at `/workflow`. Click **Select folder**, choose
the unpacked folder (or drop the `.zip`), set the name to `MD equilibration`, then click
**Open**. Paths are made relative to the folder you picked, which becomes the upload root.
Nothing leaves your computer.

**3. Add the three steps.** In the file tree, press **+** next to each mainfile (shown in
bold), in order:

| File | Rename to (double-click the node) |
| --- | --- |
| `Emin/mdrun_Emin.log` | Geometry Optimization |
| `Equil-NPT/mdrun_Equil-NPT.log` | Equilibration NPT Molecular Dynamics |
| `Prod-NVT/mdrun_Prod-NVT.log` | Production NVT Molecular Dynamics |

`.log` files are recognised as simulations, so NOMAD's default system and calculation links
are added for them automatically.

**4. Add the inputs and outputs.** Under **Add nodes**, add:

* **Input system**, renamed to `input system`;
* **Output system**, renamed to `output system`;
* **Output calculation**, renamed to `output properties`.

Inputs and outputs reference the last entry of the section list (`run/0/system/-1`), the
form NOMAD's docs use. To reference the first one instead, for example the starting
structure, set **Section** to *First (0)* in the node's edit dialog.

**5. Connect them.** Select a node, then drag one of its arrows to the next node. Clicking
one arrow and then the other also works.

```text
input system → Geometry Optimization → Equilibration NPT … → Production NVT … → output system
                                                                             └→ output properties
```

Inputs and outputs take their mainfile from the step they are connected to. Direction is fixed
automatically: an arrow drawn from an output back to its step is flipped. Links that NOMAD
cannot represent are refused, such as input → output directly, or loops.

**6. Check and export.** **Simulate** shows the graph NOMAD will display, with the
engine-added default inputs and outputs dashed, plus the YAML. **Generate YAML** downloads
`workflow.archive.yaml`.

**7. Upload.** Put `workflow.archive.yaml` at the root of the folder, next to `Emin/`. Zip
the folder and upload it to NOMAD (the
[test deployment](https://nomad-lab.eu/prod/v1/test/gui/) is fine). NOMAD creates one entry
per `.log` file plus the workflow entry; its *Workflow graph* card matches **Simulate**.

The YAML is generated by the same Python engine as the SDK, running in your browser
(WebAssembly). For this example it is byte-identical to the tutorial's output, as checked
by `tests/workflow/test_spec.py` and the playground's browser test.

## B. Project workflow across uploads (Python)

Part 4 of the tutorial ties four existing uploads into one project graph: setup → MD → three DFT
runs → vibrational analysis. Do Parts 1–3 first, so that every upload is processed. Then
collect its IDs in `PIDs.json`, using the same keys as the tutorial:

```json
{
  "upload_ids": {
    "setup-workflow": "<upload id>",
    "md-workflow": "<upload id>",
    "DFT": "<upload id>",
    "analysis": "<upload id>"
  },
  "entry_ids": {
    "parameters": "<entry id of workflow_parameters.archive.yaml>",
    "md-workflow": "<entry id of workflow.archive.yaml>",
    "DFT": ["<entry id>", "<entry id>", "<entry id>"],
    "analysis": "<entry id of vibrational_analysis.archive.yaml>"
  }
}
```

These are the tutorial's nodes. The only change is the import, from
`nomad_utility_workflows.utils.workflows` to `nomad_sdk.workflow`:

```python
import json
from pathlib import Path

from nomad_sdk.workflow import (
    NodeAttributes,
    NodeAttributesUniverse,
    NomadWorkflow,
    nodes_to_graph,
)

pids = json.loads(Path('PIDs.json').read_text())
uploads, entries = pids['upload_ids'], pids['entry_ids']


def dft(i):
    return {
        'upload_id': uploads['DFT'],
        'entry_id': entries['DFT'][i],
        'mainfile_path': 'aims.out',
    }


node_attributes = {
    0: NodeAttributes(
        name='Workflow Parameters',
        type='input',
        path_info={
            'upload_id': uploads['setup-workflow'],
            'entry_id': entries['parameters'],
            'mainfile_path': 'workflow_parameters.archive.yaml',
            'archive_path': 'data',
        },
        out_edge_nodes=[1],
    ),
    1: NodeAttributes(
        name='MD Setup',
        type='workflow',
        path_info={
            'upload_id': uploads['setup-workflow'],
            'mainfile_path': 'setup_workflow.archive.yaml',
        },
    ),
    2: NodeAttributes(
        name='MD Equilibration',
        type='workflow',
        path_info={
            'upload_id': uploads['md-workflow'],
            'entry_id': entries['md-workflow'],
            'mainfile_path': 'workflow.archive.yaml',
        },
        in_edge_nodes=[1],
    ),
    3: NodeAttributes(
        name='DFT-1',
        type='workflow',
        entry_type='simulation',
        path_info=dft(0),
        in_edge_nodes=[2],
        out_edge_nodes=[6],
    ),
    4: NodeAttributes(
        name='DFT-2',
        type='task',
        entry_type='simulation',
        path_info=dft(1),
        in_edge_nodes=[2],
        out_edge_nodes=[6],
    ),
    5: NodeAttributes(
        name='DFT-3',
        type='task',
        entry_type='simulation',
        path_info=dft(2),
        in_edge_nodes=[2],
        out_edge_nodes=[6],
    ),
    6: NodeAttributes(
        name='Vibrational Analysis',
        type='output',
        path_info={
            'upload_id': uploads['analysis'],
            'entry_id': entries['analysis'],
            'mainfile_path': 'vibrational_analysis.archive.yaml',
            'archive_path': 'data',
        },
    ),
}

universe = NodeAttributesUniverse(nodes=node_attributes)  # validates the nodes
workflow = NomadWorkflow(
    destination_filename='./project_workflow.archive.yaml',
    name='NOMAD Tutorial Workflows Project',
    workflow_graph=nodes_to_graph(universe),
)
workflow.build_workflow_yaml()
```

Upload `project_workflow.archive.yaml` as a new upload and publish it. Its workflow graph
links the four uploads, and the dataset view lists all of them; see Part 4, "Upload and
publish". The tutorial's graph view (`gravis`) is optional and not needed here.

This page's snippets are run in CI (`tests/examples/test_tutorial_workflows.py`), with
placeholder IDs written into `PIDs.json`.
